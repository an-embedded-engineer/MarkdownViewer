## 指摘一覧

### 重大度: 中

#### 指摘 1: メニュー構成にタブ実装前では無効なアイテムが含まれる

| 項目 | 内容 |
| --- | --- |
| 対象箇所 | `report.md` §「メニューバー化 > メニュー構成案」 |
| 理由 | `Close Tab` / `Close Other Tabs` はタブ機能実装後でないと有効にならない。推奨実装順ではメニューバー化がタブより先（Phase 2）であるため、これらのアイテムを Phase 2 実装時にどう扱うか（省略 or disabled）が不明確。 |
| 推奨対応 | メニュー構成案に「Phase 2 時点では `Close Tab` / `Close Other Tabs` を省略または disabled とし、タブ実装（Phase 4）時に有効化する」と注記を追加する。 |

#### 指摘 2: Tauri タブモデルにおける `rootPath` / Explorer のスコープが未設計

| 項目 | 内容 |
| --- | --- |
| 対象箇所 | `report.md` §「複数タブ対応 > 推奨する状態モデル」 |
| 理由 | 現在の `read_text_file` コマンド（`lib.rs`）は `root_path` をセキュリティ境界として受け取り、ファイルがルート外にあれば拒否する。タブが別ディレクトリのファイルを開く場合、グローバルな `rootPath` では境界が崩れる。Explorer も現在は 1 ツリーのみ表示するため、「タブは同一 root 内のファイルに限定する」前提が必要だが、報告書にその前提が明示されていない。 |
| 推奨対応 | 「タブは常に現在の rootPath 内のファイルに限定する（別ディレクトリを開くには Open Folder で root を変更する）」を明示する。この前提を取るなら `rootPath` / `fileTree` はグローバル状態として維持でき、実装が大幅に単純化される。比較実装としてもこちらが合理的である。 |

#### 指摘 3: Explorer クリック挙動の設計決定が next workflow に丸投げされている

| 項目 | 内容 |
| --- | --- |
| 対象箇所 | `report.md` §「未解決事項」、§「複数タブ対応 > 推奨する状態モデル」 |
| 理由 | これは UX の好みではなく、状態モデルと `loadMarkdown` のロジックに直接影響する設計決定である。「既存タブ方式か新規タブ方式か」によって `OpenMarkdownInTabAsync` / `loadMarkdown` の分岐ロジックが変わるため、next workflow の実装者が都度判断するには影響範囲が大きい。 |
| 推奨対応 | 未解決事項から移し、推奨案を 1 つ明示する。例: 「Explorer クリックは常に新規タブで開く。ただし同一パスのタブが既に存在する場合は activate する」を推奨案とし、その根拠（重複タブ防止と直感的な操作の両立）を 1 行添える。 |

### 重大度: 低

#### 指摘 4: Avalonia レイアウト記述が実装と一致しない

| 項目 | 内容 |
| --- | --- |
| 対象箇所 | `report.md` §「Avalonia 実装」の「2 ペイン構成」 |
| 理由 | 実際の `MainWindow.axaml` は `RowDefinitions="Auto,*"` + `ColumnDefinitions="280,*"` の 2 行 2 列 Grid で、上段 Toolbar は `Grid.ColumnSpan="2"` で全幅を占める。「2 ペイン構成」という表現は左 Explorer / 右 Preview の 2 列のみを指しており、Toolbar が全幅 span であることが読み取れない。 |
| 推奨対応 | 「上段全幅 Toolbar（`ColumnSpan="2"`）、下段左 Explorer / 右 NativeWebView の 2 列構成」と補正する。ステータスバー追加時の Grid 変更提案にも影響するため正確性が望ましい。 |

#### 指摘 5: `loadMarkdown` の `isBusy` ガードとタブ単位 loading の関係が未具体化

| 項目 | 内容 |
| --- | --- |
| 対象箇所 | `report.md` §「リスク」の `isBusy` 項目 |
| 理由 | リスクとして「タブ単位 busy と全体操作抑止を分ける必要がある」とだけ記載しているが、現在の `App.tsx` では `loadMarkdown` 冒頭で `if (isBusy) return;` という hard guard がある。タブ実装時にこのガードをそのままにすると「Tab A で読み込み中は Tab B も開けない」問題が発生する。 |
| 推奨対応 | リスク記述に「`loadMarkdown` の冒頭 `isBusy` ガードはタブ単位の `isLoading` フラグに変更が必要。グローバル `isBusy` は UI 全体の操作抑止（例: Open Folder ボタン）のみに残す」と具体化する。 |

#### 指摘 6: `RecentDirectory.displayName` の生成元が未定義

| 項目 | 内容 |
| --- | --- |
| 対象箇所 | `report.md` §「最近開いたディレクトリ > 推奨データ」 |
| 理由 | `displayName` フィールドが何から生成されるか（`Path.GetFileName(path)` か、フルパスかそれとも他か）が不明。実装者が独自解釈する余地がある。 |
| 推奨対応 | 「`Path.GetFileName(path)` 相当（ディレクトリ名のみ）とし、tooltip でフルパスを表示する」と説明を 1 行追加する。 |
